# CCC (Claude Command Center) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A self-hosted coordination hub (Postgres + REST API + MCP + owner UI + CLI/hooks) where every Claude Code session reports status and receives Orchestrator instructions through an inbox, independent of any Claude account.

**Architecture:** One Node 22 process runs `.ts` source directly (native type stripping, no build). Hono serves `/api/*`, `/mcp` (MCP SDK web-standard streamable HTTP, stateless) and the static UI. It is backed by Postgres schema `ccc` through postgres.js and plain SQL migrations. An in-process `EventEmitter` wakes long-polls and the SSE stream. A zero-dependency `cli/ccc.mjs` is both the agent CLI and the Claude Code hook handler.

**Tech Stack:** Node ≥ 22.18, TypeScript 5.9.3 (typecheck only), hono ^4.13, @hono/node-server ^2.1, postgres 3.4.9 (not 4.0.0, which was released 2026-10-29), zod ^4.6, @modelcontextprotocol/sdk ^1.32, `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-01-ccc-design.md`. Read it before any task. Section refs below (§6.4 etc.) point into it.

## Global Constraints

- Postgres only; everything lives in schema `ccc`. Plain SQL migrations in `migrations/NNN_name.sql`.
- Every HTTP/MCP input is validated with Zod. Error body: `{ "error": { "code": string, "message": string } }`. 5xx bodies say `internal_error` and nothing more; details go to `console.error`.
- Message, task and question bodies are capped at 65,536 characters (`z.string().max(65536)`). Arabic and other Unicode must round-trip unchanged.
- Session names match `^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$`.
- Roles: `orchestrator | worker | helper | auditor | other`. Statuses: `working | idle | waiting_permission | blocked | paused | unreachable | offline`.
- At most one non-retired session has role `orchestrator`. Only the owner sets it.
- **Fail open (anti-goal §4):** every CLI `hook` invocation exits 0 and prints nothing on any error. Request timeout is 2000 ms, and the hook does nothing when `CCC_SESSION` or the config is missing.
- **Delivery only at end of turn (owner decision):** PostToolUse is write-only and never injects messages.
- Controls: only `pause` and `resume`. PAUSE body text (exact): `PAUSE: finish the current step, then stop and wait for RESUME.` RESUME body text (exact): `RESUME: you may continue your work.`
- Watchdog thresholds: unreachable after 15 min without heartbeat; idle ping after 60 min without activity, repeated at most hourly. Duplicate-name "still active" window: 2 min.
- Idle ping body (exact): `PING from CCC: no activity for over 1 hour. Report your status: what you are working on and what you are waiting on.`
- No redaction/PHI filtering (owner decision 2026-11-01).
- UI renders all agent-supplied text with `textContent`, never `innerHTML`.
- `tsconfig`: `strict`, `noUncheckedIndexedAccess`, `erasableSyntaxOnly`, `allowImportingTsExtensions`, `verbatimModuleSyntax`, `noEmit`. No `any`. Import local files with the `.ts` extension. No enums and no constructor parameter properties (type stripping can't erase them).
- Hook commands are `node "<abs path>/ccc.mjs" hook <event>`, with forward slashes in the path and the path double-quoted. No `.sh` wrappers.

## Review Focus

1. **CCC unreachable or slow.** A hook against a dead URL must exit 0 within about 2.5 s with empty stdout. Test in Task 8: `hook stop against closed port is silent and fast`.
2. **Agent text containing HTML/script** shown in the owner UI must render inert. Test in Task 9: `ui never uses innerHTML`. The Playwright smoke in Task 10 posts `<img src=x onerror=alert(1)>` and checks it shows as text.
3. **Two SessionStarts for the same name at the same instant** must not 500. One keeps the name and the other gets `-2`, or both resolve to one row when the Claude id is the same. Test in Task 3: `concurrent register same name never 500s`.
4. **Stop-hook loop.** With `stop_hook_active: true` and no new mail, the hook must allow the stop, and the same message must never block twice. Test in Task 8: `stop hook blocks once per message`.
5. **Windows paths with spaces** in `install-hooks` must produce a runnable, quoted command and must not clobber existing hooks. Test in Task 8: `install-hooks merges without clobbering and quotes paths`.

## REST surface (fixed here; CLI, UI and MCP depend on it)

Agent auth is `Authorization: Bearer <device token>` + `X-CCC-Session: <name>`, plus an optional `X-CCC-Claude-Session: <id>`. Owner auth is the `ccc_admin` cookie. "Any" means owner or session.

| Method + path | Who | Body / query → response |
|---|---|---|
| GET `/healthz` | public | → `{ok:true}` |
| GET `/cli/ccc.mjs` | public | → the CLI file |
| POST `/api/sessions/register` | agent | `{claudeSessionId?, cwd?, role?}` (name comes from the header) → `{session, assignedName, takeover, resume: string}` |
| GET `/api/me` | agent | → `{session, resume}` |
| POST `/api/status` | agent | `{status?, workingOn?, blocker?}` → `{session}` |
| POST `/api/heartbeat` | agent | `{activity: boolean}` → `{ok:true}` |
| GET `/api/inbox` | agent | `?peek=1` → `{messages}` (without peek, marks read) |
| GET `/api/inbox/wait` | agent | `?timeoutMs=` (cap 30000) → 200 `{messages}` or 204 |
| POST `/api/messages` | any | `{to, body, kind?: 'note'\|'instruction'}` → `{message}` |
| GET `/api/sessions` | any | → `{sessions: SessionView[]}` |
| GET/POST `/api/tasks` | any / orch | GET `?assignee=&status=`; POST `{to,title,body?}` → `{task}` |
| POST `/api/tasks/:id` | any* | `{status?, result?, blocker?}` → `{task}` |
| POST `/api/tasks/:id/assign` · `/cancel` | orch | `{to}` / `{}` → `{task}` |
| GET/POST `/api/questions` | any | GET `?status=&to=`; POST `{to, body, context?, options?, isBlocking?}` → `{question}` |
| POST `/api/questions/:id/answer` · `/withdraw` | any* | `{choice?, text?}` / `{}` → `{question}` |
| POST `/api/broadcast` | orch | `{body}` → `{count}` |
| POST `/api/control` | orch | `{target: name\|'all', action: 'pause'\|'resume'}` → `{count}` |
| POST `/api/admin/login` · `/logout` | public / owner | `{password}` → sets/clears cookie |
| GET/POST `/api/admin/devices`, POST `/api/admin/devices/:id/revoke` | owner | POST `{label}` → `{device, token}` (token shown once) |
| POST `/api/admin/sessions/:name/role` · `/retire` | owner | `{role}` / `{}` → `{session}` |
| GET `/api/events` | owner | `?session=&limit=` (≤ 500) → `{events}` |
| GET `/api/stream` | owner | SSE; each bus event is `event: ccc`, `data: {type, sessionName}` |

`orch` = owner or the session holding `orchestrator`. `*` = the permission rule is in the owning task.

```sql
  token_hash text not null unique, created_at timestamptz not null default now(), revoked_at timestamptz);
create table ccc.sessions (
  id uuid primary key default gen_random_uuid(),
  name text not null unique check (name ~ '^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$'),
  role text not null default 'worker' check (role in ('orchestrator','worker','helper','auditor','other')),
  device_id uuid references ccc.devices(id), claude_session_id text,
  superseded_claude_session_ids text[] not null default '{}', cwd text, project text, branch text,
  status text not null default 'idle' check (status in ('working','idle','waiting_permission','blocked','paused','unreachable','offline')),
  working_on text, blocker text, paused boolean not null default false,
  last_heartbeat_at timestamptz, last_activity_at timestamptz, last_wait_at timestamptz, last_ping_at timestamptz,
  retired_at timestamptz, created_at timestamptz not null default now());
create unique index sessions_one_orchestrator on ccc.sessions ((true)) where role = 'orchestrator' and retired_at is null;
create table ccc.tasks (id bigint generated always as identity primary key, title text not null, body text not null default '',
  assignee_id uuid references ccc.sessions(id), created_by text not null,
  status text not null default 'open' check (status in ('open','in_progress','blocked','done','cancelled')),
  blocker text, result text, created_at timestamptz not null default now(), updated_at timestamptz not null default now());
create table ccc.questions (id bigint generated always as identity primary key, asked_by text not null,
  addressed_to text not null, body text not null, context text, options jsonb, is_blocking boolean not null default false,
  status text not null default 'open' check (status in ('open','answered','withdrawn')),
  answer_choice text, answer_text text, answered_by text, answered_at timestamptz, created_at timestamptz not null default now());
create table ccc.messages (id bigint generated always as identity primary key, from_name text not null,
  to_session_id uuid not null references ccc.sessions(id),
  kind text not null check (kind in ('instruction','task','answer','question','control','note','ping')),
  control_action text check (control_action in ('pause','resume')), body text not null,
  ref_task_id bigint references ccc.tasks(id), ref_question_id bigint references ccc.questions(id),
  created_at timestamptz not null default now(), read_at timestamptz);
create index messages_unread on ccc.messages (to_session_id, id) where read_at is null;
create table ccc.events (id bigint generated always as identity primary key, session_id uuid references ccc.sessions(id),
  actor text not null, type text not null, payload jsonb not null default '{}', created_at timestamptz not null default now());
create index events_session on ccc.events (session_id, id desc);
```

  `addressed_to` holds `owner`, `role:orchestrator` or a session name. The spec's `delivered_at` is folded into `read_at`, because delivering a message *is* reading it (§6.4: each message blocks once).

### Task 3: Sessions (register, takeover, duplicates, roles, status, resume)

**Files:**
- Modify: `src/sessions.ts`, `src/api.ts`
- Test: `test/sessions.test.ts`

**Interfaces:**
- Consumes: `recordEvent`, `Actor`, `httpError`.
- Produces:
  - `type Role`, `type Status`
  - `type Session = { id: string; name: string; role: Role; deviceId: string|null; claudeSessionId: string|null; supersededClaudeSessionIds: string[]; cwd: string|null; status: Status; workingOn: string|null; blocker: string|null; paused: boolean; lastHeartbeatAt: Date|null; lastActivityAt: Date|null; lastWaitAt: Date|null; lastPingAt: Date|null; retiredAt: Date|null; createdAt: Date }`
  - `registerSession(sql, input: {name: string; deviceId: string; claudeSessionId: string|null; cwd: string|null; role?: Role}): Promise<{session: Session; assignedName: string; takeover: boolean}>`
  - `ensureSession(sql, name, deviceId): Promise<Session>` creates the session as `worker` if missing and un-retires it. It uses `insert … on conflict (name) do nothing`, then a select, so concurrent first calls never raise 23505. `POST /api/sessions/register` **skips** `ensureSession`: its middleware resolves only the device and the header name, then calls `registerSession`.
  - `isSuperseded(session, claudeSessionId: string|null): boolean`
  - `resolveAddress(sql, to: string): Promise<Session>`. `'orchestrator'` → the role holder, or 409 `no_orchestrator`. Otherwise the non-retired name, or 404 `unknown_session`.
  - `orchestratorHolder(sql): Promise<Session|null>`
  - `reportStatus(sql, session, {status?: 'working'|'idle'|'blocked'|'waiting_permission'|'offline'; workingOn?: string|null; blocker?: string|null}): Promise<Session>`. Sets `last_heartbeat_at`, and `last_activity_at` unless the status is `offline`. While `paused`, a reported `working`/`idle` keeps status `paused`.
  - `heartbeat(sql, sessionId, {activity: boolean}): Promise<void>`. `activity:true` → status `working` (clears a `waiting_permission` blocker) and updates both timestamps. `activity:false` updates only `last_heartbeat_at`, and turns `unreachable` back into `idle`.
  - `setRole(sql, name, role): Promise<Session>`. Moving `orchestrator` demotes the old holder to `worker` in the same transaction.
  - `retireSession(sql, name)`
  - `listSessions(sql): Promise<SessionView[]>`, where `SessionView = Session & { unread: number; pausePending: boolean; currentTask: {id: number; title: string}|null }`. `pausePending` = an unread `control/pause` message exists; `currentTask` = the latest `in_progress` task.
  - `resumeContext(sql, session): Promise<string>`, kept under 1,500 chars. It contains the name, the role, open tasks (`T<id> [status] title`), the unread count, the last `working_on`, and these standing rules verbatim:
    - `While idle, keep "ccc wait" running in the background so messages can wake you.`
    - `Report what you are working on with report_status or "ccc status".`
    - `Send results and findings to the orchestrator.`
- **Register algorithm** (§6.2). Run it in one transaction holding `pg_advisory_xact_lock(hashtext(name))`, for each candidate name `name`, `name-2` … `name-9`:
  - Missing → insert. Requested role `orchestrator` → `worker`, plus event `orchestrator_request_denied`.
  - Same `claudeSessionId`, the incoming id is null, or the stored id is null (the row was created by `ensureSession`) → reattach: adopt the incoming id and update device, cwd and heartbeat. Only non-null ids are ever appended to `superseded_claude_session_ids`.
  - The holder has `last_activity_at > now() - interval '2 minutes'` and status ≠ `offline` → try the next candidate.
  - Otherwise → takeover: append the old id to `superseded_claude_session_ids`, set the new id, status `idle`, `takeover: true`, plus event `takeover`.
  - All candidates are busy → 409 `name_exhausted`.
- REST: register, `GET /api/me`, `POST /api/status`, `POST /api/heartbeat`, `GET /api/sessions`, admin role/retire. The agent middleware adds one check: if `X-CCC-Claude-Session` is in `supersededClaudeSessionIds` → 409 `superseded`, and nothing is written.

### Task 4: Messages, inbox, long-poll, broadcast, controls

**Files:**

**Interfaces:**
- Consumes: `bus`, `recordEvent`, `resolveAddress`, `requireOrchestrator`, `Session`.
- Produces:
  - `type MessageKind = 'instruction'|'task'|'answer'|'question'|'control'|'note'|'ping'`
  - `type Message = {id: number; fromName: string; toSessionId: string; kind: MessageKind; controlAction: 'pause'|'resume'|null; body: string; refTaskId: number|null; refQuestionId: number|null; createdAt: Date; readAt: Date|null}`

  - `control(sql, actor, target: string, action: 'pause'|'resume'): Promise<number>`. `'all'` covers every non-retired non-orchestrator session. Uses the exact PAUSE/RESUME bodies from Global Constraints.
